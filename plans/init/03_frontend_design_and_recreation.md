# SPanel-Go 前端重塑与 UI 设计决策文档

将原版 PHP 混合 Smarty 的面板重构为前后端分离系统时，前端的架构模式与视觉呈现将迎来决定性的飞跃。本文档对前端的技术选型、路由设计、组件拆分，以及“1:1 复刻”与“重新创造”的抉择进行深度分析和方案设计。

---

## 1. 核心技术栈选型 (Frontend Tech Stack)

为了确保前端具备卓越的交互流畅度、工程健壮性以及绝佳的视觉感官，建议采用以下技术选型：

- **核心框架**：**Vue 3 (SFC - 单文件组件) / React** + **TypeScript**
  - **推荐理由**：采用强类型的 TypeScript，能够从根本上杜绝旧版前端 JS 代码中高频发生的 `undefined` 字段错误，让庞杂的配置项和节点数据结构在编译期就安全可靠。**Vue 3** 拥有极低的上手门槛和出色的运行效率，配合 Composition API 可以实现超高程度的逻辑复用。
- **构建工具**：**Vite**
  - **推荐理由**：现代化的打包与开发工具，提供极致的冷启动速度和热更新（HMR）体验，极速缩短迭代周期。
- **状态管理**：**Pinia** (Vue) 或 **Zustand** (React)
  - **推荐理由**：纯粹的 TypeScript 状态流，相比旧版 Vuex，其 API 极为精炼，用于暂存当前登录的 JWT Token、用户个人档案（Profile）以及全局的主题设置（暗黑/明亮模式）。
- **网络请求封装**：**Axios**
  - **推荐理由**：拦截器（Interceptors）机制极其成熟。可以在请求拦截中自动附带 JWT，在响应拦截中统一处理 `401 Unauthorized` 自动重定向以及 `ret == 0` 的错误弹窗。
- **数据可视化**：**Chart.js** 或 **Echarts**
  - **推荐理由**：原版 SPanel 中的流量消耗历史、测速曲线使用 Chart.js，我们将在新版中利用其现代版 Wrapper 进行 100% 异步加载，创造动态细腻的交互动画。
- **样式系统**：**Vanilla CSS (原生现代 CSS) + CSS Modules**
  - **遵循红线**：不使用 TailwindCSS，而是完全使用现代原生 CSS 的高级特性（如 CSS 变量、Flexbox、Grid 布局、CSS Transitions、Glassmorphism 毛玻璃效果）进行手工雕琢。通过 CSS Modules 避免全局样式冲突，保证极致的样式控制力与渲染性能。

## 2. “1:1 复刻” 还是 “重新创造”？—— UI 深度抉择

在前端改版中，我们面临的核心抉择是：**是原封不动 1:1 照抄旧版 Material 设计，还是重新创造更现代的界面？**

### 2.1 现状分析与对比

| 维度 | 旧版 Smarty Material 模板 (resources/views/material) | 重新创造现代 SPA 界面 (TypeScript + Vanilla CSS) |
| :--- | :--- | :--- |
| **技术实现** | PHP 服务器端渲染，HTML 中夹杂大量 `{$user->email}`、`{if}` 控制流，页面间跳转需要整页刷新，DOM 操作重度依赖 jQuery，逻辑零散。 | 纯前端渲染，通过 Axios 异步消费 RESTful API。页面跳转由前端 Router 瞬时切换（路由懒加载），体验极度丝滑。 |
| **视觉美学** | 基于旧版 Material Design，色调单一，阴影偏重，在 2026 年看来略显陈旧和臃肿，缺乏高级质感。 | 融合现代 **Glassmorphism (轻量毛玻璃)**、**极简主义暗黑模式**、**渐变流光色彩**与**微动特效**，带来极其惊艳的 premium 视觉体验。 |
| **适配能力** | 虽然响应式，但由于 jQuery 控件繁杂，在小屏移动端（手机浏览器/客户端内嵌 WebView）经常出现布局错位或响应迟钝。 | 采用现代 Flex/Grid 弹性布局与 CSS 媒体查询，100% 完美适配任何屏幕尺寸，在移动端拥有原生 App 般的流畅度。 |

### 2.2 最终决策方案：**功能 1:1 复刻，视觉 100% 重新创造 (Feature Parity, Visual Recreation)**

> [!IMPORTANT]
> **绝对禁止字面意义上的 HTML 结构 1:1 照抄。**
> 因为 Smarty 页面高度耦合了 PHP 后端渲染逻辑，且旧版 Material CSS 早已过时。
> 我们的方案是：**功能上 100% 继承并对齐 SPanel 的所有业务功能；视觉上重新设计一套充满科技感、轻量、高端的界面，并默认提供令人惊叹的主题暗黑模式。**

## 3. 全新 UI 设计规范系统 (Design System)

我们将通过精心设计的 CSS 变量，在 `src/assets/styles/variables.css` 中建立一套全局色彩与微动效系统，告别任何生硬的普通原色：

```css
:root {
  /* HSL 调和色彩 */
  --bg-main: #0a0b10;
  --bg-card: rgba(20, 21, 30, 0.7);
  --bg-card-border: rgba(255, 255, 255, 0.08);
  
  --color-primary: #6366f1;       /* 科技靛蓝 */
  --color-primary-glow: rgba(99, 102, 241, 0.15);
  --color-success: #10b981;       /* 翡翠绿 */
  --color-warning: #f59e0b;       /* 琥珀金 */
  --color-danger: #ef4444;        /* 珊瑚红 */
  --color-text-main: #f3f4f6;     /* 极轻灰 */
  --color-text-muted: #9ca3af;    /* 磨砂灰 */
  
  /* 现代渐变色 */
  --gradient-brand: linear-gradient(135deg, #6366f1 0%, #a855f7 100%);
  --gradient-success: linear-gradient(135deg, #059669 0%, #10b981 100%);
  --gradient-card-hover: linear-gradient(180deg, rgba(99, 102, 241, 0.05) 0%, rgba(20, 21, 30, 0.7) 100%);

  /* 微动效与毛玻璃 */
  --backdrop-blur: blur(12px);
  --transition-smooth: all 0.3s cubic-bezier(0.4, 0, 0.2, 1);
  --shadow-premium: 0 10px 30px -10px rgba(0, 0, 0, 0.7);
}
```

- **交互微动画**：所有卡片、按钮在悬停（Hover）时，加入柔和的物理缩放（`scale(1.02)`）与渐变色流光过渡，使界面充满“生命力”。
- **极简卡片布局**：节点卡片加入国旗徽章、即时延迟指示灯（绿色表示优良，黄色代表中等，红色代表失联），摒弃杂乱的信息，优先突出关键倍率和剩余流量。

## 4. 前端页面映射与模块划分 (Page Mapping)

### 4.1 用户中心路由 (`/user/*`)

用户中心采用单侧边栏的 Dashboard 视效框架：

1. **总览控制台 (Dashboard / Home)**
   - **核心组件**：
     - **流量环形图**：使用 SVG 弧度动画展示“已用上行 + 已用下行 vs 总可用配额”，鼠标悬停可查看精确至 MB 的具体数字。
     - **快捷订阅卡片**：聚合 Clash, Surge, Sing-box 订阅链接，提供一键复制与“一键导入客户端”的快捷协议按钮。
     - **公告轮播墙**：提取最新公告，支持无刷新弹窗阅读 Markdown 详情。
     - **快速签到区**：点击触发粒子撒花动效，展示获取的签到奖励。

2. **节点列表页面 (Node Explorer)**
   - **核心组件**：
     - **节点过滤条**：快速过滤中转、直连、原生解锁、延迟高低。
     - **状态卡片**：展示节点名、倍率（如 `1.5x`）、在线人数、延迟、解锁信息。
     - **抽屉式详情 (Drawer)**：点击卡片从右侧滑出详细面板，动态渲染流量限速、使用占比以及测速图表。

3. **商店与购买中心 (Shop & Orders)**
   - **核心组件**：
     - **卡片式套餐列表**：直观对比不同套餐的流量配额、等级限制、有效期限。
     - **结算浮层**：支持优惠券动态校验（异步打折）、余额扣减、跳转扫码收银台。
     - **已购历史明细**：表格形式分页展示 bought 表里的所有扣费记录与自动续费开关。

4. **客户支持与工单 (Tickets)**
   - **核心组件**：
     - **工单列表**：按状态（处理中、已回复、已结案）分类。
     - **聊天式对话框**：管理员与用户的往来消息以微信对话的形式呈现，支持发送 Markdown 格式代码块，极大提升阅读舒适度。

5. **配置与安全中心 (Profile Settings)**
   - **核心组件**：
     - **基础信息修改表单**：修改邮箱、联络方式、面板主题。
     - **代理信息修改表单**：修改连接端口、SS 密码、混淆。
     - **双因子认证 (2FA)**：扫描二维码、生成 GA Key 绑定。

---

### 4.2 管理员控制台路由 (`/admin/*`)

管理员面板采用侧边双栏架构，支持大数据量的高效操作：

1. **全站统计看板 (System Stats)**
   - **核心组件**：
     - **关键数据卡片**：今日流水、活跃用户、在线节点数、昨日新增。
     - **财务与流量趋势图**：使用双折线图展示近 30 天的每日收入波动与总计流量吞吐。

2. **节点动态管理系统 (Node Manager)**
   - **核心组件**：
     - **节点配置表单**：涵盖节点名称、类型、中转映射、端口限制、解锁模板选择。
     - **关联 DNS 状态指示器**：当编辑或删除节点时，直观提示其绑定的 Cloudflare DNS 记录是否成功同步，避免黑节点域名失效占用。

3. **用户账户透视系统 (User Controller)**
   - **核心组件**：
     - **全局大表单**：支持大文本快速搜索，多维度条件组合筛选。
     - **代客登录 (Simulated Login)**：一键模拟用户状态，用于排查用户连接和充值故障。
     - **流量调配器**：快捷加减用户余额、等级、流量，支持批量发送公告封禁。

4. **账务与优惠卡券 (Finance & Coupons)**
   - **核心组件**：
     - **交易流水表**：展示 paylist 与 bought 扣费流水。
     - **卡密生成器**：支持批量生成包含面额、有效期的充值卡密，提供 Excel 一键导出。

## 5. 前后端分离状态管理与鉴权机制

```text
[ 前端 Axios 拦截器 ]  ---> 携带 JWT Token ---> [ 后端 v1/user 接口 ]
         ^                                           |
         |                                           v
    ( 401 报错 ) <--- 账号在别处登录/JWT过期/超5个IP <--- [ JWT 校验拦截 ]
         |
         v
[ 擦除 Pinia 状态 ] ---> 清除 LocalStorage ---> [ 重定向至 /auth/login ]
```

1. **登录鉴权**：
   - 登录成功后，后端将 `token`（JWT，含有失效时间）随 JSON 返回。
   - 前端接收到后存入 `pinia` 状态库并同步写入系统的 `localStorage` 缓存。
2. **防异地/防滥用强制掉线**：
   - 所有的 API 请求都配置 Axios 拦截器，一旦接口返回 `401 Unauthorized`（说明 Token 被后端 Redis 黑名单拉黑），前端自动触发注销逻辑，擦除 `pinia` 状态，返回登录页并弹窗提示：“您的账号已在其他地区登录，或登录 IP 数量超过限制，已安全退登。”
3. **加载优化 (Perceived Performance)**：
   - 使用 **Skeleton Screen (骨架屏)** 代替生硬的 Loading 菊花图，保证用户在数据拉取过程中，依然拥有优雅、稳定的视觉轮廓，极大提升软件的“高级感”。
